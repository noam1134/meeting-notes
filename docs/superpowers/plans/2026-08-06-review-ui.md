# Review UI Implementation Plan (addendum to meeting-notes-app plan)

**Goal:** Replace the bare-bones session browser with a real review UI, and fix window activation so the window reliably appears (with a dock icon while it's open).

**Approved by user 2026-08-06** (mockup shown: sidebar grouped by day, category filter chips, note cards with screenshot thumbnails, search, status filter, "Copy for Claude").

### Task R1: Review UI + activation

**Files:**
- Create: `Core/Sources/MeetingNotesCore/CategoryStyle.swift` (+ test)
- Create: `App/Sources/ImagePreview.swift`
- Rewrite: `App/Sources/SessionBrowser.swift`
- Modify: `App/Sources/MeetingNotesApp.swift`, `App/Sources/MenuContent.swift`

**Requirements (binding):**
1. **Activation:** "Browse Sessions" and Settings must front the window: `NSApp.activate(ignoringOtherApps: true)` on open. While the browser window is visible: `NSApp.setActivationPolicy(.regular)` (dock icon appears); back to `.accessory` when it closes. Track via the browser view's `onAppear`/`onDisappear`.
2. **Sidebar:** sessions grouped by day ("Today", "Yesterday", else `d MMM yyyy`), newest first. Row: name, start time, note count; pending sessions show orange pending-count badge, processed show green check, active session shows red record dot and sorts first. Unreadable sessions in their own section, red triangle.
3. **Toolbar:** search field filtering note text (case-insensitive); status filter (All / Pending) as segmented control.
4. **Detail pane:** header = name, `HH:mm`–`HH:mm` + date, status badge, **Copy for Claude** button → writes to `NSPasteboard`: "Process my meeting notes in <absolute folder path>: read session.json and the PNG screenshots, expand each note into full context, create Trello cards via the Trello MCP for notes categorized 'Trello task', then set each handled note's status and the session status to \"processed\"." Category chip row with per-category counts; clicking a chip toggles filtering to that category. Note cards: color category chip, `HH:mm` time, status (orange "pending" text / green check), note text (16pt), screenshot thumbnail max height 160 with rounded corners — click opens a sheet (`ImagePreview`) with the full-size image, scrollable/zoomable (magnification gesture or fit-to-window + scroll), Esc/close button dismisses.
5. **Category colors:** deterministic. `CategoryStyle.colorIndex(for category: String, in categories: [String]) -> Int` in Core: index of the category in the settings list modulo palette size; unknown categories hash (stable — sum of unicode scalars) modulo palette size. App maps index → fixed SwiftUI palette `[.purple, .teal, .orange, .pink, .blue, .green]`. Core function gets a unit test (known list order, unknown-category stability, empty list).
6. **Freshness:** refresh session list on window `onAppear` AND on `NSApplication.didBecomeActiveNotification` (so Claude's external `session.json` edits show without relaunch). Selected session's detail re-reads from disk on each selection change (existing behavior kept).
7. **Empty states:** no sessions → "No meetings yet — press ⌃⇧N or ⌃⇧S during your next meeting"; filters match nothing → "No notes match".
8. **Keep:** corrupt-session handling (Unreadable section, detail shows explainer + Reveal in Finder, file never touched).
9. Global constraints from the original plan still bind (DEVELOPER_DIR prefix, only KeyboardShortcuts dep, schema untouched — this task must NOT change Models/SessionStore/session.json).
