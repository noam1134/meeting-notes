# Pipeline Features Plan (addendum): embedded Claude terminal, Trello backlinks, pending nudge

**Approved by user 2026-08-06 (night).** Three features turning the app into a capture→Claude→Trello pipeline.

### Task P1: Trello backlinks (schema extension + UI + contract)

- `Core Models.swift`: `Note` gains `var trello: String?` (card URL). Decode with `decodeIfPresent` (old sessions parse); encode ALWAYS (null when absent) — schema stays explicit. Update `testJSONFieldNamesMatchSpec` (note keys now include `trello`) + add round-trip/null tests. This is a deliberate, backward-compatible contract change.
- `SessionStore`: no signature changes needed (updateNote mutate covers writes).
- `SessionBrowser` note card: when `note.trello != nil`, show a small "Trello" chip (blue capsule, arrow.up.right icon) next to the status — click opens the URL (`NSWorkspace.shared.open`).
- Contract text: update README's Claude-workflow list AND the Copy-for-Claude prompt in SessionBrowser: after creating each card, write its URL into that note's `trello` field; then flip statuses.

### Task P2: Embedded Claude terminal ("Process with Claude")

- New SPM dependency: SwiftTerm (https://github.com/migueldeicaza/SwiftTerm, from: 1.2.0) — approved by user for this purpose.
- New `App/Sources/ClaudeTerminal.swift`: window controller (pattern of BrowserWindowController) hosting SwiftTerm's `LocalProcessTerminalView`; spawns `/bin/zsh -l -c "claude <quoted prompt>"` in a PTY (login shell so the user's PATH finds `claude`); window titled by session name, resizable (PTY resize wired), closes on process exit + Esc guard against accidental close while running (confirm if process alive).
- `SessionBrowser` detail header: primary "Process with Claude" button (replaces nothing; sits next to Copy for Claude) → opens the terminal window with the same processing prompt for the selected session. Disabled for processed sessions.
- If spawn fails (claude not found), surface via `state.lastError` with a hint ("install Claude Code CLI or use Copy for Claude").

### Task P3: Pending badge + morning notification

- Menu bar: MenuBarExtra label becomes icon + pending-session count text when > 0 (sessions with status pending and not active).
- `UNUserNotificationCenter`: request permission on first enable; daily 09:00 local check (UNCalendarNotificationTrigger) — schedule/refresh a notification "N meeting sessions waiting for processing" whenever pending count changes; remove when zero. Settings toggle "Morning reminder" (default on, per user choice).

Constraints: session.json change is P1's ONLY schema change; DEVELOPER_DIR build prefix; conventional commits; manual smoke deferred to user.
